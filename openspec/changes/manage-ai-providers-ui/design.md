## Context

See [proposal.md](proposal.md) for background and motivation.

Currently, `Program.cs` reads `AiProviderOptions` once at startup from `IConfiguration.GetSection("Ai")` and registers a single static `IChatClient` in DI. If a user wants to change the provider, switch model names, test a different endpoint, or enter a new API key, they must manually modify `appsettings.json` or `.NET` user secrets and restart the web server.

## Goals / Non-Goals

**Goals:**
- Provide a responsive Web UI at `/Settings` for selecting the active AI provider and configuring provider-specific options (models, endpoints, API keys, and model aliases).
- Maintain dynamic runtime reconfiguration of the active `IChatClient` so updates apply immediately to proposal analysis requests without restarting the web server.
- Persist updated settings to local storage (e.g., `ai-settings.json` or local configuration store) so configuration changes survive application restarts.
- Add a visible Settings navigation link in the site header (`_Layout.cshtml`).
- Validate provider settings on submission with friendly error messages and preserve non-empty existing API keys when unedited.

**Non-Goals:**
- User authentication / multi-user role permissions.
- Live API connectivity ping testing against third-party endpoints.

## Decisions

### Decision 1: Dynamic Chat Client Provider (`DynamicChatClientProvider` / Delegating `IChatClient`)
- **Choice**: Introduce an `IAiConfigurationService` that manages current `AiProviderOptions` in memory and on disk (`ai-settings.json`), accompanied by a delegating `DynamicChatClient` that implements `IChatClient` by forwarding calls to the active provider client generated by `ChatClientFactory`.
- **Rationale**: Keeps `ProposalAnalysisService` and `AddChatClient` DI registrations decoupled from provider lifecycle changes while allowing instantaneous provider switching.

### Decision 2: Local Persistent Storage for UI Settings
- **Choice**: Store user modifications in a local JSON file (`ai-settings.json` in the application environment) with fallback to initial `IConfiguration` defaults on startup.
- **Rationale**: Simple, zero-dependency, durable persistence that does not overwrite source-controlled `appsettings.json`.

### Decision 3: UI Layout & Navigation
- **Choice**: Create `SettingsController` and `Views/Settings/Index.cshtml` styled with ProposalIQ design conventions (Bootstrap, card containers, clear field labels, and provider-specific configuration panels). Add a Settings navigation item with a sliders/gear icon in `_Layout.cshtml`.
- **Rationale**: Matches the existing theme and UI aesthetics seamlessly.

### Decision 4: Sensitive API Key Handling
- **Choice**: Mask existing keys in the UI (e.g., displaying `●●●●●●●● (Saved)` or placeholder) and retain the existing stored key if the user leaves the API key input field empty on form submission.
- **Rationale**: Prevents accidental erasure or cleartext exposure of API keys during routine settings inspection.

## Risks / Trade-offs

- **[Risk]** Switching to `FoundryLocal` when its model is not downloaded yet.
  → **Mitigation**: Trigger `FoundryLocalModelPreparationService` or model preparation asynchronously upon selecting `FoundryLocal`, and the existing readiness banner on the homepage informs the user while disabling the analyze button until ready.
- **[Risk]** Invalid endpoint URLs or missing required fields.
  → **Mitigation**: Perform server-side validation in `SettingsController` before updating configuration, displaying actionable error alerts on the Settings view if validation fails.

## Migration Plan

1. Create `IAiConfigurationService` and `JsonFileAiConfigurationService` managing runtime options persistence.
2. Implement `DynamicChatClient` implementing `IChatClient` that consults `IAiConfigurationService`.
3. Create `SettingsController` and `Views/Settings/Index.cshtml` supporting provider switching and field updates.
4. Update `_Layout.cshtml` with navigation link to `/Settings`.
5. Update `Program.cs` to register the dynamic AI configuration services.
6. Add unit tests for `SettingsController`, configuration persistence, and dynamic chat client switching.
